## C. 问题设定

### C1. 解决什么路由问题？

> **提示：** 精确到变体级别——CVRP? VRPTW? EVRP-TW? Truck-Drone?

这篇不是解一个具体问题，而是提出一个**通用框架**。它做了四个问题：
- **TSP**（旅行商）：基本款，一个推销员，访问所有城市一次
- **CVRP**（有容量约束的 VRP）：多了车辆容量限制，需要多辆车
- **OP**（定向问题）：有预算限制，节点有奖励，目标最大化奖励
- **PCTSP**（有奖金的 TSP）：可以跳过节点但需要收集足够奖励

我们项目要用的主要是 TSP 和 CVRP 部分的代码，然后自己改 decoder context 加入时间窗和充电约束。

### C2. 问题描述

> **提示：** 用自己的话描述：有哪些节点？车有什么限制？目标是什么？

以 TSP 为例：输入是 N 个城市（或者说客户）的二维坐标，输出是一个排列顺序，使得按这个顺序走一圈的总路径长度最小。CVRP 多了 depot（仓库）和容量约束——每辆车装货不能超过 C，装满就得回 depot。

论文很有意思的点在于，**同一个网络架构**，只改解码器的 context vector 就能解四个不同的问题。比如 TSP 的 context = [图嵌入, 起点, 当前位置]，CVRP 的 context = [图嵌入, 剩余容量]。这种模块化设计很聪明。

### C4. 目标函数

> **提示：** 最小化什么？

**最小化总路径长度**（total tour length）。在训练时用负值作为奖励 R = -L(π)，因为 RL 默认最大化奖励。

### C5. 核心约束公式（摘录 1~3 个）

> **提示：** 用 LaTeX 或文字描述，不是抄全文，而是挑最重要的。

```
自回归分解：
P(π | s) = ∏_{t=1}^{N} p_θ(π_t | π_{1:t-1}, s)

意思是：整个访问序列的概率 = 每一步选择下一个节点的条件概率的连乘积。
模型在每一步 t 根据"已经去过哪"来决定"下一步去哪"。
```

用 mask 保证可行性：把已经访问过的节点的 logit 设为 -∞，softmax 后概率就是 0，这样就不会走回头路了。

## D. 方法总结

### D1. 方法类别

（精确求解 / 启发式 / 元启发式 / DRL / 混合方法 / 数学规划）

**DRL（深度强化学习）**，具体是策略梯度方法 REINFORCE + Attention-based Encoder-Decoder

### D2. 方法流程

> **提示：** 用文字或伪代码描述主流程，抓住关键步骤。

```
训练流程（一个 batch）：
1. 随机生成 512 个问题实例（N 个城市坐标）
2. Encoder：对所有城市做 3 层 Multi-Head Attention → 每个城市一个 embedding h_i + 图 embedding h_bar
3. Decoder：自回归生成路线，每步用 cross-attention 计算"下一个去哪"的概率
4. 采样一条完整路线 π，计算总长度 L(π)
5. 用 Rollout Baseline 做 b(s) = 当前最优模型贪婪解码的路径长度
6. Gradient: ∇ = (R(π) - b(s)) · ∇ log p(π|s)，更新参数
7. 每 epoch 结束跟 baseline 模型比一下，如果显著更好就用当前模型替换 baseline
```

### D3. 关键算子/组件

> **提示：** 论文中最核心的技术细节是什么？

1. **Multi-Head Attention (MHA)**：核心。8 个头同时算，每个头从不同"视角"看城市间的关系。公式 `Attention(Q,K,V) = softmax(QK^T/√d_k)V`。Q 是"我要找谁"，K 是"我是谁"，V 是"我的信息"。
2. **Rollout Baseline**：不用 Critic 网络，直接用模型自己的贪婪解码结果做 baseline。无偏估计，不需要额外参数。这算是最优雅的设计之一了。
3. **Mask 机制**：把不可行动作的 logit 设为 -∞，保证输出合法解。不同问题用不同 mask 规则。
4. **Glimpsing (tanh clipping)**：解码器用 `C·tanh(u)` 把 logit 裁剪到 [-10, 10]，据说能防止 softmax 过于极端。

### D4. 使用的求解器/框架

PyTorch（没说具体版本，但看代码风格应该是 1.x），不需要 CPLEX 之类的 OR 求解器。训练时自己生成随机实例。

### D5. 核心创新点

> **提示：** 这篇论文相比已有工作有什么新东西？

1. **用 Transformer 取代 LSTM 做编码器**：之前的 Pointer Network 用 RNN，但城市的输入顺序会影响结果（城市本应是无序集合）。Transformer 的 self-attention 天然是排列等变的——输入顺序不影响输出，这跟组合优化的本质很契合
2. **Rollout Baseline**：完全不需要 Critic 网络，用"模型去年的版本"做 baseline，既稳定又优雅
3. **同一框架解多个问题**：只改 context vector，不改网络结构，就能从 TSP 换到 CVRP/OP/PCTSP。这种通用性在组合优化领域之前没有
4. **性能接近经典算法**：TSP100 上采样 1280 次后跟最优解差 0.63%，CVRP 上甚至超过了 OR-Tools

### D6. 关键假设

> **提示：** 论文做了哪些简化和假设？这些假设靠谱吗？

1. **二维欧氏空间**：假设所有城市在 [0,1] 正方形里均匀随机采样，距离用欧氏距离。实际物流是地球表面/道路网络，差挺多的——不过 TSP 学术圈都这么干，算约定俗成
2. **N 固定训练**：训练时 N=20/50/100 分别训练，换规模要重新训练。不过论文展示了泛化：N=50 训的模型在 N=100 上也能用，虽然差了些
3. **只关心距离**：没考虑时间、成本、交通等因素。对实际物流来说太简化了
4. **所有节点可达**：假设任意两个城市之间都能直达。城市路网不是这样的

## F. 深入理解

### F1. 最重要的一个公式

> **提示：** 精确抄下公式，并用自己的话翻译它在说什么。

**公式：**
```
Attention(Q, K, V) = softmax(Q · K^T / √d_k) · V
```

**我的翻译：**
这个公式是整篇论文的灵魂。它说的是：对于每个城市 i，我要产生一个新的"表征"——这个表征是所有其他城市信息的加权平均。权重 = 城市 i 的"查询" Q_i 和每个城市 j 的"键" K_j 的相似度（点积越大越关注）。除以 √d_k 是为了防止点积太大导致 softmax 变成 one-hot（梯度消失）。最后乘上 V_j 就是加权混合。

说白了就是：**每个城市在"看"完所有其他城市后，更新自己对全局的理解**。

### F2. 最精妙的一个设计

> **提示：** 论文中哪个设计让你觉得最聪明？为什么？

**Rollout Baseline**。最妙的是——它太简单了但效果太好。不用多训练一个 Critic 网络去预测 baseline，直接拿"去年的自己"做比较对象。"去年的我"贪婪解码出来的路径长度，跟"现在的我"采样出来的路径长度一对比，就知道"现在的我"进步了没有。这个想法优雅到了"为什么之前没人想到这一步"的程度。

而且它有自动提升机制：当现在的模型显著好于 baseline 时（用 t-test 检验），baseline 被替换。这样 baseline 永远在追赶但永远追不上——类似于狗追兔子的设定。

### F3. 最困惑的一个地方

> **提示：** 哪个部分你没完全理解？打算怎么搞懂？

**为什么 tanh clipping (C=10) 要这么设？** 论文说把 logit 限制在 [-10,10] 防止 softmax 太极端。但我试了试算一下：softmax(10) / softmax(0) ≈ e^10 ≈ 22026，已经非常极端了。C=10 是不是太大了？为什么不设小一点比如 C=5？这个参数感觉像是试出来的（调参出来的），缺乏理论解释。

还有一个困惑：**CVRP 的 depot 返回时机是怎么让模型学会的？** 模型需要在容量快满时"主动"选择回到 depot，但 RL 的 reward 是在整条路线结束时才给的，中间的 depot 决策怎么学到？可能是 mask 机制硬屏蔽了超载的选择，但模型仍然需要学会"哪个时机回去比较好"——这个 credit assignment 问题怎么解决的？

打算后面看源码的时候仔细跟一下 CVRP decoder 部分。

### F4. 用一句话给同学讲这篇论文

> **提示：** 不超过 3 句，用最通俗的话说清楚这篇论文干了什么。

用 Transformer 的注意力机制取代了传统的启发式搜索，让神经网络自己学会给一堆城市规划最短路线。训练方式像玩游戏：走出一条路线后，看看比"上次的最佳成绩"好多少，好了就奖励自己，差了就惩罚。同一个架构刷刷改几行就能解 TSP、VRP 等好几个不同的问题。

## G. 对我们的项目有什么用？

### G1. 可以直接借鉴的

> **提示：** 哪些想法、公式、算子可以直接用？

1. **Encoder-Decoder + Attention 架构**：这是最基础的，我们的 EVRP-TW 本质上也是序列决策，可以直接套用这个架构，然后修改 decoder context 和 mask
2. **自回归解码 + Mask 机制**：我们的约束更复杂（时间窗、电量、容量），但本质是一样的——每一步算 logits，mask 掉不可行选择，softmax 采样。可以加多个 mask 叠加
3. **Rollout Baseline**（如果可以的话）：训练的时候用贪婪解码的旧模型做 baseline，简单稳定。不过我们的问题比 TSP 复杂很多，不知道 baseline 是否还能稳定

### G2. 需要修改适配的

> **提示：** 哪些想法好，但需要改才能适合我们的场景？

1. **Node embedding 需要加更多特征**：原文只用了二维坐标，我们需要加需求量、时间窗、服务时间、节点类型（客户/充电站/仓库）等等。编码器部分要改
2. **Decoder context 需要扩展**：原文 CVRP 的 context = [图嵌入, 剩余容量]。我们需要加：剩余电量、当前时间、当前节点类型等。context 会变长很多
3. **充电站可重复访问**：原文的 mask 机制假设每个节点最多访问一次，但充电站可以被同一辆车多次访问（来回都经过）。这是个很麻烦的修改——需要允许 mask 对充电站"解锁"

### G3. 不适合我们场景的

> **提示：** 哪些假设在我们的项目中不成立？

1. **每个节点访问一次**：我们的充电站可以被重复访问，这是根本性的差异
2. **纯欧氏距离**：我们的项目如果真的要落地，可能需要用实际道路网络距离，而不是欧氏——虽然学术界很多论文也都是用欧氏的
3. **N 固定训练**：原文要 N=100 就训一个 N=100 的模型。我们的 EVRP-TW 规模变化（客户数、充电站数都可能变），需要更好的泛化能力
