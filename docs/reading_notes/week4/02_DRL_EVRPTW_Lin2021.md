## C. 问题设定

### C1. 解决什么路由问题？

> **提示：** 精确到变体级别——CVRP? VRPTW? EVRP-TW? Truck-Drone?

**EVRPTW**（Electric Vehicle Routing Problem with Time Windows），正是我们项目要做的变体。涉及：
- 电动车（电池容量 + 能耗 + 充电）
- 时间窗（每个客户有 [e_i, l_i] 时间窗，早到必须等，晚到不允许）
- 车辆容量约束

### C2. 问题描述

> **提示：** 用自己的话描述：有哪些节点？车有什么限制？目标是什么？

一个仓库、N 个客户、M 个充电站、同质电动货车若干。每辆车出发时满电，路上可以随时去充电站补电（充多少自己定，不一定充到满）。每个客户有需求量 q_i、服务时间 s_i、时间窗 [e_i, l_i]。车辆容量 C，电池容量 Q，线性能耗 r kWh/km，充电速率 g kW。目标是**最小化总行驶距离**（或距离+时间的加权）。

真实场景确实是这样：快递公司的电动车一早出发，中午可能要去充个电才能跑完下午的路线。调度员需要同时规划"走哪条路线"和"什么时候去充电"。

### C3. 约束清单

| # | 约束 | 是否包含? | 补充说明 |
|---|------|:---------:|----------|
| 1 | 车辆容量 (Capacity) | ☑ | 累计需求量不能超过车辆载重 C |
| 2 | 客户时间窗 (Time Windows) | ☑ | 硬约束，[e_i, l_i]，早到要等到 e_i，晚到不可行 |
| 3 | 服务时间 (Service Time) | ☑ | 每个客户有固定服务时间 s_i，计入时间线 |
| 4 | 电池容量 (Battery Capacity) | ☑ | Q kWh，不能低于 0（抛锚）也不能超充 |
| 5 | 能耗率 (Energy Consumption) | ☑ | r kWh/km，与距离正比（简化线性能耗） |
| 6 | 充电站 (Charging Stations) | ☑ | M 个充电站，充电站可重复访问（这点很重要） |
| 7 | 充电速率 (Charging Rate) | ☑ | g kW，恒速率充电，充电量 = 充多少自己决定 |
| 8 | 最大路线时长 (Max Duration) | □ | 没明确提，但时间窗和时间累积隐含了限制 |
| 9 | 多车型 (Heterogeneous Fleet) | □ | 所有车同质 |
| 10 | 充电站容量 (Station Capacity) | □ | 假设充电站无限容量，不排队 |
| 11 | 卡车-无人机同步 | □ | — |
| — | 充电量离散化 | ☑ | 论文把充电量离散为几个档位（50%, 75%, 100%）便于模型选择 |

### C4. 目标函数

> **提示：** 最小化什么？

```
minimize: w1 × total_distance + w2 × total_time + w3 × n_vehicles + penalties
```

但实际实验好像**主要优化总距离**，时间和车辆数通过约束间接控制。训练时奖励 = 负距离。

### C5. 核心约束公式（摘录 1~3 个）

> **提示：** 用 LaTeX 或文字描述，不是抄全文，而是挑最重要的。

```
电量约束（出发→到达）：
y_j ≤ Y_i - r × d_ij × x_ij + Q × (1 - x_ij)
意思是：到达 j 的电量 = 离开 i 时电量 - 消耗电量，但不能低于 0 或超过 Q

充电时间：
充电时间 = (B_departure - B_arrival) / g
即充了多少 kWh 除以充电功率（kW），就是充了多久

时间递推：
a_j = max(e_j, departure_time_i + travel_time(i→j))
早到要等，按 e_j 算；正常或迟到按实际到达时间
```

## D. 方法总结

### D1. 方法类别

（精确求解 / 启发式 / 元启发式 / DRL / 混合方法 / 数学规划）

**DRL**，具体是 AM（Kool 2019）架构 + **REINFORCE with Critic Baseline**

### D2. 方法流程

> **提示：** 用文字或伪代码描述主流程，抓住关键步骤。

```
编码阶段：
1. 每个节点编码为多维度特征：[坐标, 需求量, 时间窗起止, 服务时间, 节点类型]
2. 线性投影 + 3 层 Multi-Head Attention → 节点嵌入 h_i + 全局嵌入 h_bar

解码阶段（逐步生成路线）：
3. Context = [h_bar, h_current, 剩余容量, 剩余电量, 当前时间]
4. Cross-attention 计算每个可选节点的 logit
5. 多个 Mask 叠加：
   - 容量 Mask：屏蔽需求量 > 剩余容量的客户
   - 电量 Mask：屏蔽到达后电量 < 0 的节点（客户），充电站不屏蔽
   - 时间窗 Mask：屏蔽无法在时间窗内到达的节点
   - 访问 Mask：屏蔽已访问客户（但充电站可以恢复）
   - 充电站特殊处理：同一站可以多次访问
6. Softmax 采样下一个节点 → 更新状态 → 回到步骤 3
7. 到达 depot 时路线结束，开始奖励计算

训练：
8. Critic 网络预测路线长度 V(s) 做 baseline
9. 课程学习：TSP → CVRP → VRPTW → 完整 EVRPTW 递进训练
```

### D3. 关键算子/组件

> **提示：** 论文中最核心的技术细节是什么？

1. **多层 Mask 叠加机制**：这是这篇论文最体现工程功力的地方。传统的 AM 只有"已访问"一个 mask，现在要同时处理容量不足、电量不够、时间窗赶不上三个约束，每个都可能导致节点不可选。Mask 之间是 OR 关系——满足任何一个不可行条件就屏蔽。

2. **充电站节点的特殊处理**：充电站在解码器中有特殊地位：
   - 不被标记为"已访问"（可重复去）
   - 选中后触发充电逻辑：确定充电量 → 更新时间 → 更新电量
   - 充电量决策通过离散化处理（几个固定档位）

3. **课程学习 (Curriculum Learning)**：从简单到复杂逐步训练——先在 TSP 上学好基本路由，再学容量管理，再加时间窗，最后加充电。这避免了在复杂约束上从零开始训练的崩溃问题。实验消融也证明了如果不做课程学习，模型根本收敛不了。

### D4. 使用的求解器/框架

PyTorch，没开源代码（至少我搜了一圈没找到）。用 CPLEX 做对比实验生成的小规模精确解。

### D5. 核心创新点

> **提示：** 这篇论文相比已有工作有什么新东西？

1. **首次把 DRL（Attention Model）用于 EVRPTW**：之前 EVRPTW 都是传统运筹学方法（VNS/TS、ALNS 等），这是第一次用深度学习来解
2. **充电站可重复访问的建模**：在自回归框架中处理"可重复访问节点的序列生成"——这在之前的 DRL 路由论文里没有出现过
3. **课程学习训练策略**：针对多约束问题的稳定训练方法，对类似问题有通用价值
4. **推理速度的碾压**：训练好后 < 1 秒出解，传统方法几分钟到几十分钟

### D6. 关键假设

> **提示：** 论文做了哪些简化和假设？这些假设靠谱吗？

1. **线性能耗模型**（E = r × distance）：忽略速度、载重、坡度对能耗的影响。说实话现实中电动车能耗跟速度关系很大（高速风阻上升），所以这个假设偏弱，但在 2021 年几乎所有的 EVRPTW 论文都这么假设
2. **恒定充电速率**（g 不变）：实际锂电快充是"前段快后段慢"的非线性曲线。不过如果把充电目标设为 80% 以下，这个假设还算勉强可用
3. **充电站无限容量、不排队**：现实中热门充电站可能排队，但加入排队会让模型复杂度指数级上升，现阶段这么简化可以理解
4. **欧氏距离 + 匀速**：忽略交通拥堵和道路网络，50 km/h 恒定速度
5. **随机生成实例训练**：训练数据是 random 生成而不是实际物流数据

## F. 深入理解

### F1. 最重要的一个公式

> **提示：** 精确抄下公式，并用自己的话翻译它在说什么。

**公式：**
```
R = -(w1×total_distance + w2×total_time + w3×n_vehicles + w4×penalty_tw + w5×penalty_energy)
```

**我的翻译：**
所有目标都是负的，因为 RL 默认最大化奖励，而我们要最小化成本。惩罚项 w4、w5 是"软"引导——在可行情况下惩罚项为零，但如果模型生成了不可行解，惩罚会非常大（w4=w5=100）来告诉模型"别这么走"。这个多目标加权设计挺朴素的，但也实用。

但说实话我还是有点怀疑这个设计——w4=w5=100 是人为设的，如果设低了模型学不会守约束，设高了奖励信号被惩罚淹没了。感觉像调参调出来的。

### F2. 最精妙的一个设计

> **提示：** 论文中哪个设计让你觉得最聪明？为什么？

**课程学习 (Curriculum Learning)**。这个设计解决了一个很实际的问题：如果你直接在一大堆约束上训练，模型会"蒙"——每一步可选的节点少（被各种 mask 筛掉了），探索空间被压缩到几乎为零，梯度信号太弱。

课程学习从 TSP（最宽松）开始，让模型先学会"走好路线"这个基本能力。然后逐步加约束：容量 → 时间窗 → 充电。每一阶段的模型权重作为下一阶段的初始化。这样模型是"逐层累加技能"而不是"一次性学所有技能"。

我在想能不能反过来用——先训一个完整的 EVRPTW 模型，然后把它用在没有充电站的场景（相当于 fallback 到 VRPTW）？这样的话一个模型管多种业务场景。

### F3. 最困惑的一个地方

> **提示：** 哪个部分你没完全理解？打算怎么搞懂？

**充电站的"可重复访问"在代码层面怎么实现的？** 论文说了充电站不被标记为已访问，但问题是如果在路线中出现了 A→Station1→B→Station1→C 这种情况，解码器怎么区分"第一次去 Station1"和"第二次去 Station1"？如果是同一个 node embedding，模型怎么知道上次去的时候充了多少电、这次还需不需要去？

我猜是用"虚拟副本"——把每个充电站复制多份（比如 3 份），相当于 Station1_a, Station1_b, Station1_c 是不同的节点但在同一位置。但这样节点数量膨胀了，attention 成本也上去了。这个细节论文没说清楚，可能需要看代码或者邮件问作者。

另一种可能是：充电决策不是在解码器里做的，而是解码器选"客户"，充电站是事后根据电量约束自动插入的。但这样就不算端到端学习了...

### F4. 用一句话给同学讲这篇论文

> **提示：** 不超过 3 句，用最通俗的话说清楚这篇论文干了什么。

把论文 1（AM）的路由大脑装到了电动车上，教会它同时考虑"往哪开""什么时候去""电够不够""需不需要绕路充电"。训练是从简单到复杂一步步来的，先学走直线，再学看容量，再学守时间，最后才学管电量。训好后一秒出方案，但方案质量目前还比不上老师傅（传统启发式）。

## G. 对我们的项目有什么用？

### G1. 可以直接借鉴的

> **提示：** 哪些想法、公式、算子可以直接用？

1. **Node embedding 的特征设计**：[坐标, 需求量, 时间窗, 服务时间, 节点类型]——这个特征列表可以直接拿过来用，省得自己琢磨
2. **课程学习的训练流程**：TSP → CVRP → VRPTW → EVRPTW 的递进设计，我们的训练不稳定时可以考虑
3. **多 Mask 叠加机制**：容量 mask + 电量 mask + 时间窗 mask + 访问 mask 的组合方式

### G2. 需要修改适配的

> **提示：** 哪些想法好，但需要改才能适合我们的场景？

1. **充电量离散化**：原文把充电量离散为几个档位让模型选。我们能不能直接用连续充电量（比如一个 regressor 输出充多少 kwh）？感觉连续值更灵活但训练更难
2. **Critic Baseline vs Rollout Baseline**：这篇用了 Critic 网络做 baseline，但论文 1 的 Rollout Baseline 不需要额外网络。我们需要在自己的项目里比较一下哪个更稳定
3. **虚拟副本 vs 重复节点**：充电站的表示方式需要自己设计。虚拟副本简单但占资源，重复节点更自然但需要改解码器逻辑

### G3. 不适合我们场景的

> **提示：** 哪些假设在我们的项目中不成立？

1. **随机生成实例训练**：如果我们最后要用真实物流数据测试（比如京东的某天订单），随机生成的数据分布跟真实数据差太远，泛化会有问题
2. **同质车队**：我们的场景可能有多种车型（不同电池大小、不同载重），需要 heterogeneous fleet

### 新研究想法

> **提示：** 读完本文后产生了什么新想法？

这篇论文让我意识到：**Mask 机制承担了所有可行性约束的实现，但它太"硬"了**——一个节点要么完全可选要么完全不可选。我在想能不能用"软 mask"：不是把 logit 设为 -∞，而是乘一个折扣因子。比如电量快不够时，去充电站的 logit 加一个 bonus，去远距离客户的 logit 打折扣。这样模型有更平滑的学习信号。

另外，课程学习的方法启发了我：是否能训练一个"基础路由模型"然后针对不同约束做 fine-tune，而不是每个场景从头训？类似于 NLP 里的 pretrain + finetune 范式。
