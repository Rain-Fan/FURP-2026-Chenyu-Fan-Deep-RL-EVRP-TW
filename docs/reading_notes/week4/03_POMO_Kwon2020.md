## B. 为什么选这篇论文？

> **提示：** 这篇论文与你的项目有什么关系？解决了你遇到的什么问题？

这篇论文不是直接做 EVRP-TW，但它对我们很关键，因为它基本是在论文 1 Attention Model 的训练方法上做了一次很有效的升级。我们如果后面要在 AM 上加时间窗、电量和充电站，训练会比 TSP/CVRP 难很多，所以不能只关心模型结构，还要关心训练怎么稳定。

POMO 最吸引我的地方是它没有新造一个很复杂的网络，而是抓住了路由问题的一个“看起来很小但很重要”的性质：同一条最优路线可以有多个等价表示。比如 TSP 从城市 1 开始写和从城市 5 开始写，本质上是同一圈。以前模型可能被迫学习“哪个点应该作为第一个点”，但这个问题其实没有意义。POMO 干脆让模型从多个点同时出发，把这些等价最优解都利用起来。

对我们的项目来说，它可能可以作为训练策略，而不是作为完整求解器。也就是说：EVRP-TW 的约束由我们自己加，POMO 的多起点 rollout 和 shared baseline 可以拿来提高训练稳定性。

## C. 问题设定

### C1. 解决什么路由问题？

> **提示：** 精确到变体级别——CVRP? VRPTW? EVRP-TW? Truck-Drone?

论文实验里做了三个组合优化问题：

- **TSP**：旅行商问题，访问所有节点一次并回到起点
- **CVRP**：带容量约束的车辆路径问题，需要从 depot 出发，用多条 route 服务所有客户
- **0-1 Knapsack Problem (KP)**：不是路由问题，用来证明 POMO 不只适用于路径类问题

和我们最相关的是 TSP/CVRP 部分。POMO 本身没有时间窗、电池、充电站这些约束，所以它不是 EVRP-TW 论文。但它可以当作 AM 的训练增强版。

### C2. 问题描述

> **提示：** 用自己的话描述：有哪些节点？车有什么限制？目标是什么？

以 TSP 为例，输入是一组二维坐标点，模型要输出一个访问顺序，使得整圈总距离最短。关键点是：同一个环路有很多种序列表示。比如 `(1,2,3,4)`、`(2,3,4,1)`、`(3,4,1,2)` 其实都是同一条路线，只是起点不同。

CVRP 多了 depot、客户需求量和车辆容量。车辆从 depot 出发，装载量不能超过容量，服务一部分客户后可以回 depot，再开始下一条 route。这里的对称性比 TSP 弱一些，因为不是所有客户都适合作为一条最优解的“第一个访问客户”，但论文还是简单粗暴地把所有客户都当作起点，结果也很好。

### C4. 目标函数

> **提示：** 最小化什么？

对 TSP/CVRP 来说，目标是**最小化总路径长度**。在强化学习里通常写成最大化 reward，所以 reward 可以理解成 `R = - route_length`。

对 KP 来说目标是最大化背包价值，但这个和我们项目关系不大。

### C5. 核心约束公式（摘录 1~3 个）

> **提示：** 用 LaTeX 或文字描述，不是抄全文，而是挑最重要的。

```
自回归策略：
π_t = p_θ(a_t | s),                         t = 1
π_t = p_θ(a_t | s, a_1:t-1),                t = 2,...,M

意思是：模型一步一步选节点，后面的选择依赖前面已经选过的节点。
```

```
POMO policy gradient:
∇J(θ) ≈ (1/N) Σ_i (R(τ_i) - b_i(s)) ∇ log p_θ(τ_i | s)

其中 τ_i 是从第 i 个起点开始 rollout 得到的一条解。
```

```
Shared baseline:
b_shared(s) = (1/N) Σ_j R(τ_j)

意思是：同一个 instance 上的 N 条 rollout 互相比较。
比平均值好的轨迹被强化，比平均值差的轨迹被压低。
```

## D. 方法总结

### D1. 方法类别

（精确求解 / 启发式 / 元启发式 / DRL / 混合方法 / 数学规划）

**DRL**，具体是 **Attention Model + REINFORCE + POMO shared baseline**。它不是传统启发式，也不是精确算法，而是训练一个神经网络构造解。

### D2. 方法流程

> **提示：** 用文字或伪代码描述主流程，抓住关键步骤。

```
训练阶段（以 TSP/CVRP 为例）：
1. 随机生成一个 batch 的问题实例
2. 用 Attention Model encoder 编码所有节点，只编码一次
3. 对每个实例选择 N 个不同起点
   - TSP: 每个城市都作为起点
   - CVRP: 简单地把所有客户都作为起点
4. 从每个起点并行 rollout，得到 N 条解 τ_1, ..., τ_N
5. 分别计算每条解的 reward R(τ_i)
6. 用 N 条 reward 的平均值作为 shared baseline
7. 对每条轨迹计算 advantage = R(τ_i) - mean(R)
8. 用 REINFORCE 更新策略网络

推理阶段：
1. 从 N 个起点分别 greedy rollout
2. 选其中距离最短的一条
3. 如果用 instance augmentation，则对坐标做 8 种翻转/旋转变换
4. 对 K 个增强实例 × N 个起点都 greedy rollout，再取最好解
```

### D3. 关键算子/组件

> **提示：** 论文中最核心的技术细节是什么？

1. **Multiple starting nodes**：不再让模型自己猜第一个点，而是强制从多个起点同时出发。对 TSP 这种环路问题特别自然，因为任意节点都可以作为同一最优环的起点。

2. **Shared baseline**：这是我觉得 POMO 真正厉害的地方。以前 AM 的 rollout baseline 是拿当前采样解和 greedy 解比；POMO 是拿同一个 instance 的多条 rollout 互相比。这样 baseline 不需要额外网络，也不需要复制旧模型，计算上更便宜。

3. **Multiple greedy rollouts for inference**：训练完以后也不只跑一条 greedy 路线，而是从多个起点跑多条 greedy 路线，再选最好的。这个比普通 sampling 更稳定，因为 greedy 不引入随机噪声。

4. **Instance augmentation**：对二维坐标做 8 种对称变换，比如 `(x,y)`、`(y,x)`、`(1-x,y)`、`(x,1-y)` 等。理论上路线长度不变，但模型看到的输入形式变了，可能输出不同的候选解。

### D4. 使用的求解器/框架

PyTorch。论文明确说代码开源，仓库是 `https://github.com/yd-kwon/POMO`。网络结构用的是 Kool 2019 的 Attention Model。

训练硬件里提到 TSP100 一个 epoch 在单张 Titan RTX 上约 7 分钟，训练到 200 epochs 大概 1 天，完整跑到 2000 epochs 约 1 周。

### D5. 核心创新点

> **提示：** 这篇论文相比已有工作有什么新东西？

1. **把“多个等价最优解”显式用于训练**：不是简单采样多条轨迹，而是从不同起点构造有意义的多条轨迹。
2. **提出 shared baseline**：同一个 instance 内部的多条轨迹互相做 baseline，降低方差，而且训练不容易卡在局部最优。
3. **推理阶段也利用对称性**：multi-greedy + 8 倍增强让解质量明显提升，尤其是 TSP100 gap 从 AM greedy 的 3.51% 降到 0.14%。
4. **保持架构简单**：没有换掉 AM，没有引入复杂 critic，主要改训练和推理方式。

### D6. 关键假设

> **提示：** 论文做了哪些简化和假设？这些假设靠谱吗？

1. **问题存在对称性/多个等价表示**：TSP 很成立，CVRP 部分成立，EVRP-TW 就要小心。因为时间窗和电量会让“从不同点开始”不一定等价。
2. **二维欧氏坐标**：TSP/CVRP 都是在单位正方形随机生成，和真实路网差距明显。但这是和 AM 保持一致的标准设置。
3. **无时间、电量和服务过程**：POMO 只处理基础路由，不处理复杂资源状态。我们项目不能直接套结果。
4. **所有起点都值得尝试**：TSP 成立；CVRP 其实不严格成立，论文也承认不是所有客户都适合作为最优序列的起点，只是实验上效果仍然好。

## F. 深入理解

### F1. 最重要的一个公式

> **提示：** 精确抄下公式，并用自己的话翻译它在说什么。

**公式：**
```
b_shared(s) = (1/N) Σ_{j=1}^{N} R(τ_j)
```

**我的翻译：**

这就是 POMO 的 shared baseline。对于同一个问题实例，模型从 N 个不同起点生成 N 条路线，然后把这 N 条路线的平均 reward 当作 baseline。某条路线如果比平均值好，它对应的决策就被强化；如果比平均值差，就被削弱。

这个公式看起来很简单，但比我一开始想象的更巧。它不是和“外部标准答案”比，也不是和另一个 critic 网络比，而是让模型在同一个样本内部自己比较。这样 baseline 天然跟实例难度匹配：难实例大家都差，容易实例大家都好，不会被不同实例之间的尺度差异干扰。

### F2. 最精妙的一个设计

> **提示：** 论文中哪个设计让你觉得最聪明？为什么？

**多起点 rollout。** 它聪明在没有强行引入复杂理论，而是把路由问题本来就有的对称性吃干净了。

以前我读 AM 时觉得 START token 很自然：模型先输出第一个点，再输出后面的点。但 POMO 让我意识到，对 TSP 来说“第一个点是谁”其实是一个伪问题。你让模型去学一个没有唯一答案的问题，等于白白增加训练难度。POMO 直接绕过这个问题：既然每个点都可以是起点，那就每个点都跑一遍。

这个想法对 EVRP-TW 不一定能原样搬过来，因为时间窗和电量状态会破坏很多对称性。但“不要让模型学习没有必要学习的东西”这个原则很值得记住。

### F3. 最困惑的一个地方

> **提示：** 哪个部分你没完全理解？打算怎么搞懂？

我现在最困惑的是：**POMO 到 EVRP-TW 后还剩多少对称性？**

TSP 是闭环，所以从哪个城市开始写都一样。CVRP 虽然有 depot，但不同 route 的顺序、同一 route 内部的起始客户也还有一些等价性。可是 EVRP-TW 有时间窗，路线通常是从 depot 在时间 0 出发，客户访问顺序和当前时间强绑定；再加上电池状态，很多“看起来等价”的序列其实不等价。

所以如果我们直接把“所有客户都作为起点”用于 EVRP-TW，可能会产生很多根本不合理的 rollout。也许更合理的做法是：只对每条 route 内部的客户顺序做增强，或者对充电站插入位置做多候选，而不是照搬 TSP 的所有节点起点。

打算后面看 POMO 代码时重点看 `select_start_nodes` 怎么写，再想 EVRP-TW 里能不能设计一个“可行起点筛选器”。

### F4. 用一句话给同学讲这篇论文

> **提示：** 不超过 3 句，用最通俗的话说清楚这篇论文干了什么。

它发现路由问题里很多最优解只是“从不同点开始写”的同一条路线，于是让模型从多个起点同时练习，而不是纠结第一个点该选谁。训练时多条路线互相比，推理时多条 greedy 路线取最好。结果是在不大改网络的情况下，把 AM 的效果明显往前推了一截。

## G. 对我们的项目有什么用？

### G1. 可以直接借鉴的

> **提示：** 哪些想法、公式、算子可以直接用？

1. **Shared baseline**：可以尝试替代 AM 的 rollout baseline，尤其是我们训练 EVRP-TW 时，如果 critic 不稳定，POMO baseline 可能更省事。
2. **多候选 greedy 推理**：即使训练不用 POMO，推理时也可以从不同初始策略/不同 depot route 构造方式生成多条解，再取最好。
3. **Instance augmentation 思路**：如果我们用的是欧氏坐标实例，可以做旋转、翻转增强；如果是道路网络，这个就不能直接用。

### G2. 需要修改适配的

> **提示：** 哪些想法好，但需要改才能适合我们的场景？

1. **起点选择不能无脑用所有客户**：EVRP-TW 有时间窗，晚窗客户不适合作为早期起点。可能要按可达性、时间窗起点、电量可行性筛选起点。
2. **Shared baseline 需要考虑可行性**：如果某些 rollout 不可行，reward 里有大惩罚，平均 baseline 可能被污染。需要区分可行解和不可行解，或者只用可行 rollout 算 baseline。
3. **增强方式要保留约束含义**：坐标翻转对欧氏距离成立，但如果时间窗、需求量、充电站功率不变，理论上还能用；如果后面用真实路网距离矩阵，就不能随便翻转坐标了。

### G3. 不适合我们场景的

> **提示：** 哪些假设在我们的项目中不成立？

1. **TSP 式环路对称性不完全成立**：EVRP-TW 有 depot、时间 0、电量初始状态，不能随便循环平移序列。
2. **只优化距离太简单**：我们还要管充电等待、时间窗违约、电量可行性，reward 会复杂很多。

### 新研究想法

> **提示：** 读完本文后产生了什么新想法？

POMO 提醒我，很多时候模型训练难不是因为网络不够强，而是我们把问题表示得太别扭。对 EVRP-TW 来说，也许不应该让模型直接从零学会“何时去充电站”。可以给它多个可行充电候选方案，让模型在这些候选里比较，类似 POMO 让多条轨迹互相比。

另一个想法是做 **constraint-aware POMO**：不是所有节点都做起点，而是根据当前时间窗、电量、容量筛出一组“有希望的起点/候选动作”，再在这组里面做 shared baseline。这样可能比原版 POMO 更适合 EVRP-TW。
