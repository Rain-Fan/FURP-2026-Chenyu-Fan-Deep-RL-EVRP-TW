## B. 为什么选这篇论文？

> **提示：** 这篇论文与你的项目有什么关系？解决了你遇到的什么问题？

这篇是 EVRP-TW 方向绕不开的基础论文。前面几篇 DRL 论文更多是在讲“怎么用神经网络解路由”，但 Schneider 这篇是在定义“EVRP-TW 到底是什么”。如果不读它，后面很容易把电池约束、充电站访问、时间窗这些东西写得很随意。

我选它主要有两个原因。第一，它给了一个比较完整的数学模型，包括时间、载重、电量、充电站重复访问这些变量怎么放进 MIP。第二，它提出了标准 benchmark 的生成方式，后面 Lin 2021 也用它来做测试，所以它相当于是我们项目的“问题定义 + 数据标准”。

这篇读起来不像 DRL 论文那么“新”，公式也比较硬，但它对我们项目的帮助反而更直接：我们要知道哪些约束必须严格满足，哪些地方可以先简化。

## C. 问题设定

### C1. 解决什么路由问题？

> **提示：** 精确到变体级别——CVRP? VRPTW? EVRP-TW? Truck-Drone?

**E-VRPTW / EVRP-TW**：Electric Vehicle Routing Problem with Time Windows and Recharging Stations。

它可以理解为 VRPTW + 电动车电池约束 + 充电站。和普通 VRPTW 相比，最关键的新增点是：车辆中途可能需要去充电站，否则电量不够；而充电会消耗时间，进一步影响客户时间窗。

### C2. 问题描述

> **提示：** 用自己的话描述：有哪些节点？车有什么限制？目标是什么？

问题里有一个 depot、一批客户和若干充电站。每辆电动车从 depot 出发，最后回到 depot。客户必须且只需服务一次，每个客户有需求量、服务时间和时间窗。车辆有载重容量 C 和电池容量 Q，行驶距离会按固定比例消耗电量。

车辆可以在路线上访问充电站，而且同一个充电站可以被多次访问。论文为了在 MIP 里表示“同一站可重复访问”，把充电站复制成 dummy vertices，也就是 F'。这个设计很重要，因为普通 VRP 模型一般默认节点最多访问一次。

目标是分层的：**第一目标最小化车辆数，第二目标最小化总行驶距离**。论文的公式里目标函数写的是总距离，但文字明确说车辆数优先，这也是 VRPTW 领域常见做法。

### C3. 约束清单

| # | 约束 | 是否包含? | 补充说明 |
|---|------|:---------:|----------|
| 1 | 车辆容量 (Capacity) | ☑ | 每辆车剩余货量 u，客户需求 q_i，不能为负 |
| 2 | 客户时间窗 (Time Windows) | ☑ | 硬时间窗，服务不能晚于 l_i 开始，早到可等待 |
| 3 | 服务时间 (Service Time) | ☑ | 客户服务时间 s_i 计入时间递推 |
| 4 | 电池容量 (Battery Capacity) | ☑ | 电量 y 在 [0,Q] 内，不能途中耗尽 |
| 5 | 能耗率 (Energy Consumption) | ☑ | 线性能耗 r · d_ij |
| 6 | 充电站 (Charging Stations) | ☑ | 可访问充电站，使用 dummy copies 允许重复访问 |
| 7 | 充电速率 (Charging Rate) | ☑ | 线性充电，充电时间与缺电量成正比 |

### C4. 目标函数

> **提示：** 最小化什么？

层级目标：

1. **先最小化使用车辆数**
2. **在车辆数相同的情况下最小化总行驶距离**

论文的 MIP 目标函数写为：

```
min Σ_i Σ_j d_ij x_ij
```

但实际算法评价时，会先比较车辆数，再比较距离。也就是说，少一辆车永远优于距离稍短但车更多的方案。

### C5. 核心约束公式（摘录 1~3 个）

> **提示：** 用 LaTeX 或文字描述，不是抄全文，而是挑最重要的。

```
客户访问约束：
Σ_j x_ij = 1,  ∀ i ∈ I

意思是：每个客户必须被离开一次，也就是每个客户只服务一次。
```

```
充电站离开后的时间递推：
τ_i + t_ij x_ij + g(Q - y_i) - (l_0 + gQ)(1 - x_ij) ≤ τ_j

意思是：如果从充电站 i 去 j，那么到达 j 的时间 =
到达充电站 i 的时间 + 行驶时间 + 把电充满所需时间。
```

```
电量约束（从客户/仓库出发）：
0 ≤ y_j ≤ y_i - r d_ij x_ij + Q(1 - x_ij)

意思是：如果走 arc i→j，到达 j 的剩余电量不能超过
出发时电量减去路上消耗，也不能低于 0。
```

## D. 方法总结

### D1. 方法类别

（精确求解 / 启发式 / 元启发式 / DRL / 混合方法 / 数学规划）

**元启发式 / 混合启发式**。具体方法是 **Variable Neighborhood Search (VNS) + Tabu Search (TS)**，并且 VNS 的接受准则用了类似 Simulated Annealing 的 Metropolis probability。

### D2. 方法流程

> **提示：** 用文字或伪代码描述主流程，抓住关键步骤。

```
VNS/TS 主流程：
1. 预处理，删掉明显不可行的 arc
   - 容量不可能
   - 时间窗不可能
   - 电池容量不可能

2. 构造初始解
   - 按 depot、随机点、客户之间的角度排序
   - 逐个把客户插入 route
   - 容量或电池不够时开新 route

3. 进入 feasibility phase
   - 允许不可行解存在
   - 用惩罚函数评价容量、时间窗、电量违约
   - 如果长期找不到可行解，就增加车辆数

4. VNS shaking
   - 用 cyclic-exchange 在多个 route 之间交换客户/站点序列
   - 产生一个扰动解 S'

5. Tabu Search intensification
   - 从 S' 开始做若干轮局部搜索
   - 操作包括 2-opt*, relocate, exchange, stationInRe
   - tabu list 防止刚删掉的 arc 立刻加回来

6. SA-style acceptance
   - 更好的解一定接受
   - 更差的解按温度概率接受，前期更容易跳出局部最优

7. 找到可行解后，进入 distance minimization phase
   - 车辆数固定
   - 继续优化总距离
```

### D3. 关键算子/组件

> **提示：** 论文中最核心的技术细节是什么？

1. **Dummy vertices for stations**：把充电站复制成多个虚拟节点 F'，这样 MIP 和局部搜索都能表达“同一充电站可重复访问”。这个点对我们写 DRL mask 很有启发。

2. **Generalized cost function**：

   ```
   F(S) = L(S) + αP_cap(S) + βP_tw(S) + γP_batt(S) + P_div(S)
   ```

   也就是允许暂时不可行，但用惩罚项控制搜索方向。这个比一开始就强行保证全可行更灵活。

3. **stationInRe operator**：专门插入或删除充电站的邻域操作。普通 VRPTW 的 2-opt、relocate 不够，因为 EVRP-TW 的充电站不是普通客户，它可能需要动态插入。

4. **电量和时间窗违约的快速计算**：论文为了让局部搜索快，维护 forward/backward 的容量、电量、时间窗信息，很多 move 的违约变化可以 O(1) 计算。

### D4. 使用的求解器/框架

主要算法是作者自己实现的 Java 单线程程序。小规模实例用 CPLEX 做对比，验证 VNS/TS 的解质量。

实验机器是 Intel Core i5 2.67 GHz、4 GB RAM、Windows 7 Professional。这个硬件现在看很老，所以它的运行时间反而挺有参考价值。

### D5. 核心创新点

> **提示：** 这篇论文相比已有工作有什么新东西？

1. **正式提出 E-VRPTW 模型**：把电池容量、充电站、客户时间窗和车辆容量放进同一个 VRP 模型里。
2. **充电时间依赖到站电量**：不像 G-VRP 那样固定 refuel time，而是根据剩余电量计算充电时间，更符合电动车场景。
3. **设计 EVRP-TW benchmark**：基于 Solomon VRPTW 生成 100 客户 + 21 充电站的大实例，以及 5/10/15 客户的小实例。
4. **混合 VNS/TS 效果强**：VNS 负责跳大邻域，TS 负责深挖局部，SA 接受准则进一步提升探索能力。

### D6. 关键假设

> **提示：** 论文做了哪些简化和假设？这些假设靠谱吗？

1. **线性能耗 r · distance**：忽略车速、坡度、载重、温度。学术模型里常见，但真实电动车能耗明显更复杂。
2. **线性充电且充到满**：论文假设在充电站把电充到 Q，充电时间和缺电量线性相关。现实快充通常是非线性的，而且很多调度不会每次充满。
3. **充电站无限容量**：不考虑排队、充电桩数量、占用冲突。现实中这可能很重要。
4. **欧氏距离和固定行驶时间**：基准实例基于坐标距离，不是真实道路网络。
5. **同质车队**：所有车辆容量、电池容量、能耗率一样。

| 算例规模 | 本文方法 | 基线方法 | Gap | 运行时间 | 可行性 |
|:---------|:---------|:---------|:----|:---------|:------|
| 5客户 | VNS/TS 基本达到 CPLEX 解 | CPLEX | 0% | 约 0.1-0.2s | 可行 |

补充几个重要数字：

- 小规模 36 个 EVRP-TW 实例里，只要 CPLEX 在 7200s 内找到最优解，VNS/TS 都能找到同样的最优解。
- 100 客户实例的消融实验里，完整 VNS/TS 平均 gap 是 **0.35%**，去掉 SA 接受准则后是 **0.46%**，纯 TS 是 **0.75%**。
- 在 G-VRP 小实例上，VNS/TS 对 CPLEX 上界的平均 gap 是 **-0.09%**，平均时间约 **0.65min**。
- 在 G-VRP 大实例上，MCWS/DBCA 平均比 VNS/TS 差将近 **15%**。

这篇的结果挺扎实。它不是只说“我们方法不错”，而是用小实例跟 CPLEX 验证、用大实例做消融、还拿相关问题的 benchmark 证明泛化能力。

## F. 深入理解

### F1. 最重要的一个公式

> **提示：** 精确抄下公式，并用自己的话翻译它在说什么。

**公式：**
```
F(S) = L(S) + αP_cap(S) + βP_tw(S) + γP_batt(S) + P_div(S)
```

**我的翻译：**

这是启发式搜索里的评价函数。`L(S)` 是路线总距离，后面三个 P 是容量、时间窗、电量违约惩罚，最后 `P_div` 是多样化惩罚，用来避免搜索一直在差不多的解附近打转。

我觉得这个公式很实用，因为 EVRP-TW 太容易出现“差一点可行”的解。如果硬性要求每一步都可行，搜索空间会被切得很碎，可能很难从一个可行区域跳到另一个可行区域。允许暂时不可行，再用惩罚把它拉回来，是传统启发式很成熟的一套做法。

对 DRL 来说，这也有启发：reward 不一定只能是最终距离，也可以把容量/时间窗/电量违约拆出来作为 penalty。但 penalty 权重怎么调，会是一个难点。

### F2. 最精妙的一个设计

> **提示：** 论文中哪个设计让你觉得最聪明？为什么？

我觉得最精妙的是 **stationInRe operator**，也就是专门插入/删除充电站的邻域操作。

普通 VRP 的局部搜索大多在客户之间换顺序，比如 relocate、exchange、2-opt。但 EVRP-TW 里很多问题不是客户顺序本身，而是“中间需不需要插一个充电站”。如果没有专门处理充电站的 move，算法可能只能通过很绕的客户交换间接改变充电结构，效率会很低。

这点对我们做 DRL 也很重要：充电站不能被当作普通客户。客户是必须服务一次的任务，充电站是资源恢复点，它的访问是辅助动作。模型结构和 mask 都应该体现这个区别。

### F3. 最困惑的一个地方

> **提示：** 哪个部分你没完全理解？打算怎么搞懂？

最困惑的是论文的**完全充电假设**。公式里充电时间是 `g(Q-y_i)`，也就是到站后充到满电。这个假设让模型简单很多，因为充电站访问后电量状态固定回 Q。但现实里不一定划算：如果只差一点电就能完成后续路线，充满可能浪费大量时间，尤其有时间窗时更明显。

我想后面重点查两件事：

1. Lin 2021 里到底怎么处理部分充电，是离散档位还是连续决策；
2. 如果我们自己做 DRL，能不能把“充多少电”作为一个动作，或者先用简单规则：只充到能到下一个客户/充电站/仓库的最低安全电量。

另一个没完全搞懂的是 time travel approach 的细节。它是为了计算时间窗违约时不要把一个早期违约无限传播到后面节点，这个想法我理解，但具体 forward/backward slack 怎么 O(1) 更新，还需要配合代码或小例子再推一遍。

### F4. 用一句话给同学讲这篇论文

> **提示：** 不超过 3 句，用最通俗的话说清楚这篇论文干了什么。

这篇论文把“电动车要充电”这件事正式放进了带时间窗的车辆路径问题里。它不只是规划客户顺序，还要决定路线中什么时候去充电站，而且充电会影响能不能赶上客户时间窗。求解上用了 VNS + Tabu Search，把传统启发式做得很扎实。

## G. 对我们的项目有什么用？

### G1. 可以直接借鉴的

> **提示：** 哪些想法、公式、算子可以直接用？

1. **EVRP-TW 数学模型**：节点集合、dummy station、时间/载重/电量变量都可以作为我们建模的基准。
2. **充电站 dummy copy 思路**：如果 DRL 里不好处理重复访问，可以先复制充电站节点，限制最多访问次数。
3. **惩罚函数设计**：容量、时间窗、电量分别设 penalty，适合我们设计 reward 或训练 diagnostics。
4. **benchmark 生成方法**：基于 Solomon 实例加充电站、设置电池容量和充电速率，这可以直接用于我们的实验数据。

### G2. 需要修改适配的

> **提示：** 哪些想法好，但需要改才能适合我们的场景？

1. **完全充电要改**：我们如果追求更真实或更灵活，最好支持部分充电，否则很多路线会因为充电时间过长变差。
2. **传统局部搜索算子要换成 DRL 组件**：stationInRe 对应到 DRL 里可能是“充电站动作”或“自动插入充电站后处理”。
3. **分层目标要转成 reward**：车辆数优先、距离其次这个层级目标，在 RL 里不能简单写成 `-distance`，需要对新开车辆加很大的惩罚或分阶段训练。

### G3. 不适合我们场景的

> **提示：** 哪些假设在我们的项目中不成立？

1. **充电站不排队**：如果我们的场景要更贴近现实，需要考虑站点容量或等待时间。
2. **欧氏距离**：如果后面接真实地图，距离矩阵不再满足坐标翻转/旋转对称性，很多 DRL 增强方法也会失效。

### 新研究想法

> **提示：** 读完本文后产生了什么新想法？

可以把 Schneider 的 VNS/TS 当作“老师”来生成训练数据或 baseline。比如先用 VNS/TS 在小规模实例上生成高质量解，再用 imitation learning 预训练 AM/POMO 模型，最后用 RL fine-tune。这样可能比从零 REINFORCE 稳定很多。

另一个想法是做一个 hybrid 方法：DRL 先快速生成客户访问顺序，传统启发式再专门插入/调整充电站，相当于把最难的 EVRP-TW 拆成“客户排序”和“充电修复”两个阶段。
